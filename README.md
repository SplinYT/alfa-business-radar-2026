# Бизнес-радар

Прототип персонализированной новостной аналитики для руководителей крупных компаний. Превращает событие в объяснение каналов влияния: кредитная нагрузка, внешняя торговля, спрос, цепочки платежных контрагентов. Пользователь видит отдельно текст новости, исходные фрагменты аналитики Альфа-Банка и сценарные выводы системы.

## Состояние решения

Работает локальный сквозной прототип: вход, компании и роли, профиль группы, ранжирование, поиск по аналитике, интерпретация, проверка ссылок, повторный поиск, импорт новой новости, экспорт JSON. Интерфейс интернет-банка смоделирован, реальные банковские действия отсутствуют.

По умолчанию LLM отключена: применяется открыто обозначенный анализ по правилам. Для выполнения требования кейса об AI необходимо подключить разрешённую модель ключом организаторов и пройти сценарий с LLM. Доступ к этому ключу не предоставлен, поэтому реальный вызов разрешённой модели не проверен. Внешние новости в комплекте синтетические; есть рабочий RSS/Atom-парсер и ручной импорт нового текста. Сервис не проверяет истинность входной новости.

## Быстрый запуск

Нужны Docker Engine и Compose v2. Windows: Docker Desktop в режиме Linux containers.

```bash
cp .env.example .env
docker compose up --build -d
```

PowerShell вместо `cp`: `Copy-Item .env.example .env`.

Открыть http://localhost:8000. Пароль: `demo-radar-2026`. Выбрать `DEMO_STEEL`, роль «Финансовый директор», дату `2026-10-21`, нажать «Подготовить сводку».

Остановка: `docker compose down`. Данные остаются в volume. Базовый образ фиксирует Python 3.12.8; сторонних Python-зависимостей нет. Docker build в среде подготовки недоступен, конфигурация требует проверки на компьютере участника; Python/API тесты выполнены.

### Без Docker

Python 3.12.8, зависимости устанавливать не требуется:

```bash
python -m app.server
```

При таком запуске переменные из `.env` автоматически не читаются: экспортируйте нужные переменные в окружение. Офлайн-демонстрация работает с настройками по умолчанию. Сервер слушает `0.0.0.0:8000`; для локальной проверки ограничьте доступ настройками ОС. Compose публикует порт только на 127.0.0.1.

## Данные приложений 1 и 2

В архиве решения `data/private/` содержит три предоставленных CSV и OCR всех 64 страниц девяти аналитических PDF. Эти файлы исключены из Git и Docker image. В Git включены синтетические компании, платежи и связи, а также ограниченные OCR-фрагменты четырёх материалов банка с именами документов и номерами страниц. Исходные PDF нужно хранить рядом с проектом отдельно для сверки OCR.

Для полного набора на **первом запуске** измените в `.env`:

```dotenv
DATA_DIR=/private
```

Если база уже создана, явный повторный импорт заменяет таблицы компаний, платежей, связей, аналитики и новостей; добавленные новости будут сброшены. Сделайте копию нужной сводки перед командой:

```bash
docker compose exec radar python scripts/import_data.py /private
```

Для запуска без Docker:

```bash
python scripts/import_data.py data/private
python -m app.server
```

CSV читаются как UTF-8 с разделителем `;`; пустые поля и нечисловые значения не становятся подтверждёнными признаками. В исходных данных 85 525 строк компаний, 85 514 уникальных ID. ID U_428697 встречается 12 раз; при импорте используется последняя строка этого ID (явное упрощение, требующее уточнения у организаторов). 115 строк имеют указанную выручку >15 млрд рублей. Единица выручки трактуется как рубли; это допущение необходимо подтвердить у организаторов. Фильтр крупного бизнеса можно отключить. Платежи агрегируются по паре отправитель/получатель; период данных неизвестен. Связи физических лиц используются только для подсчёта связанных организаций, идентификаторы физлиц не передаются модели. Доля рынка не оценивается без знаменателя рынка.

Для повторного OCR на системе с Poppler, Tesseract 5 и языками rus+eng:

```bash
python scripts/ocr_bank.py /path/to/bank-pdfs data/private/bank.json
```

В поставке использован Tesseract 5 с rus, 125 dpi; после сбоя чтения одна страница перераспознана с 110 dpi. Числа, таблицы и латиницу необходимо сверять с оригиналом. В наборе есть обзор стали за 2021 год: он получает десятикратный штраф при поиске и пометку исторического источника, не передаётся LLM. Прогнозы из него нельзя выдавать за актуальные.

## Подключение разрешённой LLM

Только модели из приложения 3. В `.env`:

```dotenv
LLM_ENABLED=1
LLM_MODEL=Qwen3.6 35B A3B
LLM_MODEL_ID=идентификатор_из_выданного_шлюза
LLM_BASE_URL=https://выданный-шлюз/v1
LLM_API_KEY=личный_ключ_организаторов
MAX_LLM_CALLS_PER_RUN=2
LLM_DAILY_TOKEN_LIMIT=30000
```

Это формат конфигурации, адрес и идентификатор не являются рабочими значениями. Запросить реальные у организаторов. Совместимый контракт: `POST {LLM_BASE_URL}/chat/completions` со стандартными `messages`, `model`, `max_tokens`, `temperature`; JSON ответа в `choices[0].message.content`. Должна использоваться именно разрешённая модель, соответствующая `LLM_MODEL`; произвольный псевдоним нельзя подставлять под разрешённое имя.

После изменения `.env`: `docker compose up -d --force-recreate`.

Сервис разрешает только шесть названий из приложения 3. Не использует внешние агентные фреймворки. Минимизирует профиль, отправляемый модели; исходные ID, физлица и платежные строки в запрос не включаются. Текст загруженной новости может содержать введённые пользователем сведения: не импортируйте секреты. Фрагменты банка передаются только в выданный организаторами шлюз. LLM не получает инструменты записи, shell, URL-fetch и платёжные операции.

На сводку — до двух вызовов по умолчанию. SQLite резервирует суточный лимит до сетевого запроса; резерв не возвращается даже при ошибке, чтобы повторы не раздували расход. Это консервативная оценка токенов, **не денежный лимит**. Лимит 500 ₽ на командный ключ должен контролироваться в кабинете шлюза с учётом остальных участников и тарифов. API-ошибка/таймаут/неверная JSON-схема/неизвестная ссылка дают обозначенный fallback по правилам. Семантическую истинность автоматическая проверка ссылок не доказывает.

## Архитектура и агентная логика

`web/` → `app/server.py` (сессия/CSRF/права) → `app/core.py` (собственный оркестратор) → SQLite / извлечение аналитики / разрешённая LLM.

1. **Планирование:** определить профиль, контрагентов и нужные инструменты.
2. **Контекст:** профиль компании и группы, признаки банковских продуктов, ФТС, отрасль и платежная концентрация остаются общими для следующих шагов.
3. **Отбор:** тематические признаки, отраслевые и косвенные связи контрагентов, регион, роль и свежесть. Будущие новости исключаются относительно даты среза.
4. **Поиск:** лексический RAG по OCR-страницам; вывод связан с `document`, `page`, `id`. При пустом поиске агент расширяет запрос контекстом компании и фиксирует повторный шаг.
5. **Интерпретация:** правила связывают несколько факторов; при подключении LLM формируется структурированный JSON с проверяемыми утверждениями. Найденные упоминания замедления спроса или жёсткой риторики банка изменяют сценарии рисков, а не только показываются рядом.
6. **Самопроверка:** схема, существование ссылок и заполненность; невалидная генерация отклоняется. Результаты инструментов и предупреждения сохраняются в сводке. Журнал `audit` хранит шаги, дату и компанию без текста LLM-запросов и ключа.

Это ограниченный самостоятельный оркестратор с условными ветвями и retry, без готового автономного агента. Правила планирования прозрачны. Не заявляется открытое свободное LLM-планирование.

### Ранжирование

Сумма: подходящий продукт +25; отраслевое совпадение +30; роль казначея/ставка +12; CFO/ставка или валюта +5; CEO/спрос, логистика, труд +9; зарплатный проект/труд +8; тема деятельности получателя платежей +15×доля; отрасль группы +5; явное упоминание контрагента +35; регион +10; свежесть `max(0,10−возраст_дней/3)`. Итог ограничен 100, порог >10. Коэффициенты эвристические, не обучены и не калиброваны на экспертной разметке. Релевантность не является вероятностью риска. См. `docs/VALIDATION.md`.

## Получение новых новостей

В интерфейсе раскрыть «Добавить ранее не показанную новость», вставить фактический заголовок, дату, URL и текст. URL не загружается сервером и служит ссылкой на источник. Новость сохраняется, классифицируется и участвует в следующем ранжировании. Дедупликация по нормализованному заголовку и тексту; близкие пересказы семантически не объединяются.

RSS/Atom из явно доверенного источника:

```bash
python scripts/import_rss.py "https://доверенный-хост/реальная-лента.xml"
```

Нужно передать существующий URL ленты, а не адрес обычной статьи. По умолчанию разрешены `cbr.ru,www.cbr.ru`; `RSS_ALLOWED_HOSTS` расширяет список администратором. HTTPS, запрет редиректов и XML entities, лимит 2 MB, таймаут 15 секунд. Автоматическое расписание и проверка доступности конкретной публичной ленты в прототип не включены. HTML-описания показываются как текст, скрипты не выполняются.

## Конфигурация

| Переменная | Назначение |
|---|---|
| APP_PASSWORD | Пароль демонстрационной учётной записи |
| DATA_DIR | Импорт при отсутствии базы |
| DB_PATH | SQLite, по умолчанию `data/radar.sqlite` |
| DEMO_COMPANIES | Разрешённые компании через запятую; пусто — все в демо-наборе |
| COOKIE_SECURE | `1` для HTTPS, `0` только для локальной демонстрации |
| LLM_ENABLED | Явное включение генерации |
| LLM_MODEL / LLM_MODEL_ID | Разрешённое имя и реальный ID шлюза |
| LLM_BASE_URL / LLM_API_KEY | HTTPS API и секрет, только сервер |
| LLM_DAILY_TOKEN_LIMIT | Суточный локальный резерв токенов |
| MAX_LLM_CALLS_PER_RUN | Ограничение числа вызовов на сводку |
| RSS_ALLOWED_HOSTS | Белый список RSS-хостов |

## Безопасность и ограничения

Один тестовый аккаунт, а не production IAM. Сессии с часовым сроком, HttpOnly/SameSite, CSRF и проверка Origin; пароль сравнивается константным по времени методом. Десять попыток входа/минуту на IP. Параметризованный SQL; вывод источников экранируется. Компания проверяется по серверному allowlist. Для production необходимы SSO, отдельные пользователи/роли/tenant ACL, TLS reverse proxy, централизованный аудит и хранение секретов. На внешнем сервере не открывайте необработанный Python HTTP server напрямую: он предназначен для прототипа. Не доверяйте полю Host с внешнего трафика без корректно настроенного reverse proxy.

Prompt injection: источники объявляются недоверенными; инструменты модели не предоставляются, ссылки проверяются по allowlist полученных фрагментов. Это снижает риск, но не гарантирует смысловую корректность; эксперт проверяет гипотезы, числа и первоисточники. LLM endpoint конфигурирует администратор, UI не может его менять. Секреты и исходные клиентские CSV не коммитятся.

## Проверка экспертами

1. Запустить Compose, войти тестовым паролем.
2. Срез `2026-10-21`, DEMO_STEEL, CFO → проверить кредитный, сырьевой и контрагентский каналы.
3. Открыть источник банка → увидеть документ, страницу, полный OCR-фрагмент.
4. Переключить на DEMO_RETAIL → проверить другой состав и порядок ленты, сценарий охлаждения спроса.
5. Переключить роль → сравнить причины и баллы ранжирования.
6. Добавить незнакомую новость о кредитах, поставках или спросе; проверить появление без изменения кода.
7. Выбрать дату до всех событий → пустая лента без будущих новостей.
8. Подключить разрешённую LLM → проверить маркировку AI, claims и ссылки. При ошибке шлюза увидеть fallback.
9. Импортировать полный набор → проверить реальные обезличенные ID, группы и платежные связи.
10. Скачать JSON, проверить trace, источники и неизвестные параметры компании.

```bash
python -m unittest discover -s tests -v
```

API: `docs/API.md`. Соответствие методичке и личные действия: `docs/SUBMISSION.md`. Сторонние компоненты и ограничения прав: `THIRD_PARTY_NOTICES.md`.
