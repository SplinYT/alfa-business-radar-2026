## Что сделать лично, по порядку

1. Установить Git, Docker Desktop (Linux containers). Для удобной публикации — GitHub CLI с официального сайта. Для работы с опубликованной версией предпочтительно клонирование GitHub.
2. Клонировать https://github.com/SplinYT/alfa-business-radar-2026.git. Открыть PowerShell в корне проекта. Проверить `git log --oneline`. Полные CSV и OCR перенести из ранее выданного архива в data/private; в GitHub они не публикуются.
3. Репозиторий уже опубликован. Для последующих изменений создавать новые коммиты и выполнять `git push`. Не запускать создание второго репозитория. Удалённые SHA отличаются от локального архива, тег v0.1.0 из архива не подтверждает версию GitHub.
4. На GitHub открыть Settings → Collaborators → Add people → **alfa-hack-2026**. Проверить точное имя аккаунта жюри в актуальной инструкции организаторов, предоставить доступ и убедиться, что приглашение принято. Создание репозитория само по себе доступа жюри не даёт.
5. Получить у организаторов общий ключ, base URL и точный ID разрешённой модели. Ключ хранить только в `.env`, не загружать в GitHub. Уточнить рублёвый лимит на стороне шлюза и распределение токенов между участниками.
6. Заполнить `.env`, выполнить `docker compose up --build -d`. Подключить LLM, открыть сводку, убедиться, что хотя бы первая подходящая карточка показывает режим AI и корректные ссылки. Если виден fallback, это **не** успешная проверка LLM.
7. При необходимости импортировать полный набор `data/private`; оригинальные приложения хранить отдельно. Проверить у организаторов единицы REVENUE_COMPANY и период платежей. Не публиковать исходные клиентские CSV без разрешения.
8. Выбрать реальный разрешённый RSS-источник либо добавить свежую новость вручную с оригинальным URL; проверить новый текст, которого не было в демонстрации. Новость о текущей ставке нужно сверять с официальным источником, синтетические сценарии не выдавать за факты.
9. Пройти сценарий README. Сохранить screenshots/видео самостоятельно только если это требуется формой подачи. Никакие скриншоты в текущем комплекте не заменяют живой прототип.
10. При наличии времени развернуть за TLS reverse proxy на своём сервере, сменить пароль, COOKIE_SECURE=1, ограничить доступ и не выкладывать .env. Хостинг, домен, расходы и доступы должны быть выбраны участником; в комплекте нет обещания уже работающего внешнего адреса.
11. Зафиксировать версию до фактического дедлайна: `git rev-parse HEAD`, `git tag --points-at HEAD`; указать ссылку GitHub и хеш в форме сдачи. Дата дедлайна в приложенной методичке не указана — проверить на платформе. После любых исправлений создать настоящий новый коммит/тег; не менять даты старых коммитов.
12. Проверить форму платформы: состав команды, ссылка, доступ жюри, требуемые поля и дополнительные материалы. Самостоятельно отправить заявку и подготовиться объяснить архитектуру и ограничения на защите.

### Ручная публикация в созданный пустой репозиторий

Заменить URL на фактический адрес созданного репозитория:

```bash
git remote add origin https://github.com/YOUR_LOGIN/alfa-business-radar-2026.git
git push -u origin main
git push origin v0.1.0
```
